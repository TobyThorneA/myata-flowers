# Myata Flowers frontend

Фронтенд интернет-магазина цветов Myata Flowers. Проект отвечает за витрину букетов, каталог, карточки, избранное, форму заявки, контакты, базовую админку и интеграцию с Яндекс Метрикой.

## Суть проекта

Сайт показывает букеты из backend API:

```text
https://api-v2.myata-flowers.ru/api/bouquets
```

Пользователь может:

- смотреть главную страницу с подборками;
- открывать каталог и категории;
- просматривать карточку букета в модальном окне;
- добавлять букеты в избранное;
- отправлять заявку на подбор или заказ;
- переходить в Telegram, WhatsApp, Max или звонить;
- читать служебные страницы: доставка, оплата, гарантия, контакты, политика.

Администратор может:

- войти в `/admin`;
- создавать, редактировать и удалять букеты;
- скрывать букеты;
- менять доступность;
- загружать фото букетов.

## Как запустить локально

Установить зависимости:

```bash
npm install
```

Запустить для разработки:

```bash
npm run mob
```

Vite покажет адреса:

```text
Local:   http://localhost:5173/
Network: http://192.168.1.144:5173/
```

Для локальной разработки лучше открывать сетевой адрес компьютера:

```text
http://192.168.1.144:5173/
```

Потому что backend CORS может быть настроен на этот приватный IP, а не на `localhost`.

Подробнее про frontend/server связь: [FRONTEND_SERVER_GUIDE.md](./FRONTEND_SERVER_GUIDE.md).

## Сборка

```bash
npm run build
```

Сборка состоит из двух шагов:

```text
tsc -b
vite build
```

Если TypeScript находит ошибку, build падает. Это нормально: лучше ловить ошибки до деплоя.

## Деплой

На сервере исходники лежат в:

```text
/srv/frontend-myata
```

Продовая статика лежит в:

```text
/var/www/myata-flowers.ru
```

Типовой порядок:

```bash
cd /srv/frontend-myata
git pull
npm ci
npm run build
rsync -av dist/ /var/www/myata-flowers.ru/
```

Большой серверный tutorial: [SERVER_TUTORIAL.md](./SERVER_TUTORIAL.md).

## Что в проекте хорошо

- Проект уже решает реальную бизнес-задачу: показывает каталог, принимает заявки и ведет пользователя в мессенджеры.
- Стек нормальный для текущего размера: React, TypeScript, Vite, Redux Toolkit.
- Есть типизация сущности букета.
- Есть админка для управления каталогом.
- Есть валидация формы через Zod/React Hook Form.
- Есть категории, подборки, избранное, модалки, CTA-блоки.
- Есть интеграция с Telegram-заявками.
- Есть базовая Яндекс Метрика и цели для рекламы.
- Сайт уже можно быстро менять и деплоить.

## Что слабое

- Это SPA на Vite, поэтому SEO ограничено: страницы категорий и букетов хуже раскрываются для поисковиков, чем в SSR/SSG.
- Много данных грузится на клиенте после открытия страницы.
- Главная делает несколько запросов по категориям, из-за этого можно получить лишнюю сетевую нагрузку.
- Админка ручная и уже начинает разрастаться.
- Есть старые комментарии и куски старого кода, которые стоит почистить.
- API URL захардкожены в коде.
- Стили местами смешаны: Tailwind, SCSS, inline-подходы.
- Нет единой дизайн-системы компонентов.
- Изображения тяжелые, особенно логотип и часть ассетов.
- Нет полноценной SEO-структуры под коммерческие посадочные страницы.
- Нет отдельного слоя для контента: акции, тексты, корпоративные блоки и SEO-страницы сейчас придется добавлять руками в код.

## Что стоит улучшить в ближайшую очередь

### Технически

- Вынести API endpoints в env/config.
- Убрать закомментированные старые версии кода.
- Сократить количество запросов на главной.
- Сделать единый слой API.
- Добавить нормальные loading/error/empty states.
- Оптимизировать изображения.
- Разбить крупный JS bundle через lazy loading.
- Привести маршруты модалок к единому формату.
- Подумать о переносе контента в CMS.

### По продажам

- Усилить первый экран: яснее оффер, доставка, сроки, город, способы связи.
- Добавить блоки доверия: реальные фото, отзывы, гарантия свежести, условия замены.
- Сделать отдельные посадочные страницы под категории.
- Сделать отдельные блоки под поводы: день рождения, свидание, извинения, маме, учителю, корпоратив.
- Добавить модуль акций.
- Добавить подписки на цветы.
- Добавить корпоративные предложения.
- Упростить путь до заявки: меньше лишних действий, больше понятных CTA.
- Разделить цели Метрики по типам лидов.

## Возможный переход на Next.js

Next.js стоит рассматривать не как “модную замену Vite”, а как следующий этап, если сайт надо развивать под SEO, рекламу, посадочные страницы и контент.

Что Next может дать:

- серверный рендеринг или статическую генерацию страниц;
- хорошие SEO-страницы категорий и букетов;
- нормальные metadata для каждой страницы;
- оптимизацию изображений через `next/image`;
- route-level loading/error;
- удобные посадочные страницы под рекламу;
- возможность лучше связать сайт с CMS.

Что усложнится:

- миграция роутинга;
- перенос модалок;
- перенос клиентского Redux/состояния;
- другая модель загрузки данных;
- деплой Next-приложения сложнее, чем Vite static build;
- нужно аккуратно продумать backend/CMS/API.

## Рекомендуемый план развития

1. Сначала сделать небольшую реконструкцию текущего сайта: тексты, визуал, CTA, блоки доверия, акции.
2. Параллельно описать будущую структуру страниц: категории, поводы, корпоративные клиенты, подписки.
3. Подготовить контентную модель: bouquet, category, promotion, landing page, subscription, corporate request.
4. После этого переходить на Next.js, если реально делаем SEO/посадочные/контент.
5. Для админки рассмотреть Payload CMS, если контента станет много и его нужно удобно редактировать без кода.

## Короткий вывод

Текущий проект хороший как быстрый рабочий frontend для магазина. Он уже продает и позволяет быстро вносить изменения.

Но если цель — больше продаж, SEO, Яндекс Директ, посадочные страницы, подписки и корпоративные клиенты, проекту нужна следующая архитектурная ступень: либо аккуратная реконструкция текущего Vite-приложения, либо переход на Next.js с продуманной CMS/контентной моделью.
