# Target Sitemap

Дата: 2026-05-13.

Цель документа: спроектировать будущую карту страниц Myata Flowers для продаж, SEO,
Яндекс Директа, посадочных страниц и возможной миграции на Next.js.

Этот документ не означает немедленный переход на Next.js. Он задает целевую структуру,
которую можно внедрять поэтапно: сначала в текущем Vite-приложении, затем проверить в
Next.js POC и только потом переносить полностью.

## Принципы

- Сохраняем работоспособность текущего сайта на каждом шаге.
- Не удаляем старые URL без редиректов.
- Для SEO используем стабильные slug, а не русские названия категорий в URL.
- Категории, поводы, акции и корпоративные страницы должны иметь свои metadata.
- Страница должна иметь понятный коммерческий интент: купить, заказать, подобрать,
  узнать условия или оставить заявку.
- Client-only страницы вроде избранного не считаем SEO-страницами.
- Админку не смешиваем с публичной картой сайта.

Важно: `categorySlug` не должен быть тем же значением, что хранится в `categories` в БД.
Нужна отдельная сущность `Category`:

- `slug`;
- `title`;
- `apiKey`;
- `description`;
- `seoTitle`;
- `seoDescription`;
- `h1`;
- `heroText`;
- `sortOrder`;
- `isActive`.

### Карточки букетов

Целевая схема:

```text
/bouquet/[slug]
```

Пока backend не имеет slug, безопасная промежуточная схема:

```text
/bouquet/[id]
```

Лучший финальный вариант:

```text
/bouquet/[slug]
```

Например:

```text
/bouquet/dzhuletta
/bouquet/oblako-hrizantem
/bouquet/vecherniy-sad
```

Для обратной совместимости:

- старые `/bouquet/:id` должны открываться или редиректить на `/bouquet/:slug`;
- sitemap после появления slug должен использовать только canonical slug URL;
- Метрика `bouquet_view` должна сохраниться.

Целевая схема:

```text

```

Стартовые страницы:

| URL                     | Назначение                   |
| ----------------------- | ---------------------------- |
| `/promo`                | Все акции                    |
| `/promo/bouquet-of-day` | Букет дня                    |
| `/promo/week-deals`     | Акции недели                 |

| `/promo/card-bundle`    | Букет + открытка/дополнение  |

Старые `specialOffer` URL лучше не развивать как публичную SEO-структуру. Их можно:

- перевести в `/promo/[slug]`;
- сделать редиректы со старых `/specialOffer/:category`.

## Редиректы и совместимость

Нужно сохранить старые входы, чтобы не потерять пользователей и рекламные ссылки.

| Старый URL                    | Новый URL/поведение                         |
| ----------------------------- | ------------------------------------------- |
| `/store`                      | 301/308 на `/`                              |
| `/catalog/Розы`               | 301/308 на `/catalog/roses`                 |
| `/catalog/Хризантемы`         | 301/308 на `/catalog/chrysanthemums`        |
| `/catalog/Стойкие`            | 301/308 на `/catalog/long-lasting`          |
| `/catalog/Сезонные`           | 301/308 на `/catalog/seasonal`              |
| `/catalog/Авторские%20букеты` | 301/308 на `/catalog/author-bouquets`       |
| `/catalog/Композиции`         | 301/308 на `/catalog/flower-boxes`          |
| `/bouquet/:id`                | открыть или редиректить на `/bouquet/:slug` |
| `/specialOffer`               | 301/308 на `/promo`                         |
| `/specialOffer/:category`     | 301/308 на подходящий `/promo/:slug`        |

В текущем Vite SPA настоящие серверные 301/308 ограничены. Полноценные редиректы лучше
закладывать для Next.js или nginx. До миграции можно сделать клиентскую совместимость.

## Sitemap XML

В sitemap должны попадать:

- `/`;
- `/catalog`;
- активные `/catalog/[categorySlug]`;
- активные `/bouquet/[slug]`;
- `/promo` и активные `/promo/[slug]`;
- `/occasions` и активные `/occasions/[occasionSlug]`;
- `/subscriptions`;
- `/corporate` и активные корпоративные страницы;
- `/delivery`;
- `/payment`;
- `/contacts`;
- `/warranty`;
- `/privacy-policy`;
- `/about`.

Не должны попадать:

- `/favorites`;
- `/order`;
- `/admin`;
- `/admin/dashboard`;
- URL модалок с `backgroundLocation`;
- скрытые букеты;
- технические/дублирующие URL.

## Metadata для страниц

Минимальный набор для каждой SEO-страницы:

- `title`;
- `description`;
- `h1`;
- canonical URL;
- Open Graph title;
- Open Graph description;
- Open Graph image;
- robots index/follow;
- structured data, где уместно.

Для букетов дополнительно:

- цена;
- наличие;
- изображения;
- состав;
- категория;
- alt для изображения.

## Приоритет внедрения

### Этап 1. Безопасно в текущем Vite

- Зафиксировать slug-модель категорий в конфиге.
- Добавить будущие URL в документацию.
- Не ломать текущие русские category URL.
- Подготовить API/config слой.
- Обновить sitemap вручную или скриптом.

### Этап 2. Коммерческие страницы в текущем frontend

- Усилить `/promo`.
- Добавить `/occasions` и 2-3 первых повода.
- Добавить `/corporate`.
- Добавить `/subscriptions`.
- Не смешивать с полной миграцией.

### Этап 3. Next.js POC

- `/`;
- `/catalog/[categorySlug]`;
- `/bouquet/[slug или id]`;
- metadata;
- получение данных из текущего API;
- сохранение целей Метрики;
- проверка сборки и деплоя.

### Этап 4. Полная миграция

Только после POC и решения по CMS:

- перенос роутинга;
- перенос модалок;
- перенос форм;
- перенос Метрики;
- перенос админки или подключение CMS;
- генерация sitemap;
- редиректы;
- performance check.

- Будет ли отдельная страница города, если появятся Москва/другие города?
- Нужна ли отдельная B2B-форма или достаточно текущей формы заявки на первом этапе?
